# 操作与数据流

操作者是本地运行程序的用户。以下流程涉及原始数据完整性、模型冻结或结果写入；没有应用层身份认证。

| 流程 | 前提 | 读取与校验 | 写入与成功结果 |
|---|---|---|---|
| 标定 | 配置路径正确，至少 6 对可用图像且能分为指定折数 | 文件 ID 配对、解码、尺寸、预排除、角点；每折只训练标定子集 | 清单、角点图、C0/C2 比较、重采样、冻结模型、正式标定 CSV |
| 测试姿态 | 已完成标定 | 棋盘规格与冻结模型一致；测试 ID 和尺寸；左右正深度 | 每个预期 ID 的成功或失败行、坐标轴图、模型哈希 |
| 输出验收 | 标定和姿态文件齐全 | CSV 还原矩阵与 JSON 比较；旋转一致；重算像素误差；核验模型哈希 | verification.json；任一校验异常时非零退出 |
| 原图可视化 | 模型 CSV、观测清单存在 | 相机参数仅从 CSV 读取；图像哈希与检测时一致 | 新目录中叠加图与 HTML，不改 BMP |
| 姿态专项验证 | 5 对正式姿态已成功 | 先输出验收，再核验测试原图；读取 CSV 位姿；固定相机做角点留出 | pose_accuracy 下指标、报告和叠加图 |
| 开发质量验收 | 已安装开发依赖 | 当前 Python 启动固定工具命令，无 shell 拼接执行 | 每条命令的输出、退出码写入 quality_checks.json；任何失败导致总命令失败 |

## 异常处理与边界

原始文件只读；CSV/JSON 是程序输入边界，不应手动替换数字以改善结果。检查失败应检查上游配置、图像或重新运行相应阶段。

缺失一侧、图像解码失败或角点检测失败会在对应检测清单记录；测试流程按预期 ID 补失败行。整个图像目录为空时，数据读取会直接报错，尚不自动输出全量失败 CSV。

阶段一或二重跑会更新输出；各文件之间不是原子提交。重新标定后应继续重跑姿态和验收。可视化 HTML 是本地查看产物，不包含外部请求。

## 完整交付执行顺序

```bash
.venv/bin/python run_pipeline.py all
.venv/bin/python visualize_calibration.py
.venv/bin/python validate_pose_accuracy.py
.venv/bin/python check_quality.py --with-results
```

不需要网络访问；首次安装依赖需要访问包源。
